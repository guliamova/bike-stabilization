# 🚲 Bicycle stabilization to (0, 0, 0)

Стабилизация кинематической модели велосипеда в точке (x, y, θ) = (0, 0, 0)
из произвольного стартового положения. Три разных контроллера, бенчмарк
со статистикой и pygame-анимация.

![demo](results/demo.gif)

*Розовый — Polar Lyapunov, синий — Sampling MPC, зелёный — Heading Pursuit.
Стартуют из (-4, 2.5, -30°), цель — жёлтое колечко с указателем курса.*

![boxplots](results/boxplots.png)

---

## Модель

Кинематический велосипед, состояние `q = [x, y, θ]`, управление
`u = [v, δ]` (скорость, угол поворота переднего колеса):

```
ẋ = v · cos θ
ẏ = v · sin θ
θ̇ = v / L · tan δ
```

Параметры по умолчанию: `L = 1 м`, `|v| ≤ 2 м/с`, `|δ| ≤ 35°`,
разрешён задний ход. Интегратор — RK4, шаг 20 мс.

## Контроллеры

| | Идея | Файл |
|---|---|---|
| 🔴 **Polar Lyapunov** | Замкнутый закон в полярных координатах (Corke 4.16): `v = k_ρ·ρ`, `ω = k_α·α + k_β·β`. Кривизна `κ = ω/v` остаётся конечной у цели, что фиксирует финальный угол. | `bike/controllers/polar_lyapunov.py` |
| 🔵 **Sampling MPC** | Двухсегментный beam-search: перебираем сетку `(v, δ)` (8 × 13, без `v=0` и без малых `\|v\|`), катим вперёд H₁ шагов, оставляем top-12 первых действий, для каждого перебираем все вторые действия на H₂ шагов и берём минимум. У цели (`ρ < 0.3`) — переключение на простой аналитический park-закон. Векторизованно через NumPy. | `bike/controllers/sampling_mpc.py` |
| 🟢 **Heading Pursuit** | Простой baseline: пропорциональная обратная связь по курсу на цель, едет вперёд (или назад если цель сзади). **Не корректирует финальный θ** — упирается в цель «как попало». | `bike/controllers/heading_pursuit.py` |

> 💡 **Теорема Брокетта.** Для неголономной системы не существует
> гладкой времянезависимой обратной связи, стабилизирующей все стартовые
> позы. Поэтому 100% сходимость к (0,0,0) одним непрерывным законом
> невозможна. Polar Lyapunov сходится по позиции почти везде; финальный
> угол подбирается «в последний момент» за счёт ненулевой кривизны.

## Запуск

```bash
pip install -r requirements.txt

# 1) бенчмарк на 40 случайных стартах
python benchmark.py --n 40 --seed 42

# 2) графики ящик-с-усами
python plot_boxplots.py

# 3) интерактивная анимация (нужен дисплей)
python main.py

# 4) сгенерировать GIF без дисплея
python render_gif.py
```

### Управление в анимации

| Клавиша | Действие |
|---|---|
| `SPACE` | случайный новый старт |
| `R` | сброс с тем же стартом |
| `1` / `2` / `3` | пресет-старты |
| `TAB` | пауза |
| `+` / `-` | скорость симуляции |
| `Q` / `Esc` | выход |

Три велосипеда (по числу контроллеров) стартуют одновременно и параллельно
едут к цели — видна разница в траекториях, скоростях и в том, кто
доехал, а кто застрял.

### ⚠️ pygame и Python 3.13

Если при `python main.py` появляется

```
AttributeError: module 'pkgutil' has no attribute 'ImpImporter'
```

— это известная несовместимость старого `pygame` (≤ 2.5.1) с Python 3.13.
Лечится одним из:

```bash
pip install --upgrade pygame          # ≥ 2.5.2 уже починили
# или
pip uninstall pygame && pip install pygame-ce
# или используй Python 3.11 / 3.12
```

Альтернатива: запусти `python render_gif.py` — он не открывает окно
(SDL dummy driver) и просто сохранит результат в `results/demo.gif`.

## Метрики

`benchmark.py` сохраняет в JSON для каждого старта: достигнута ли цель
(позиция ближе 0.3 м), время достижения, длина пути, средняя |v|,
средняя |ω|, финальная ошибка позиции и финальная ошибка угла.

`plot_boxplots.py` рисует 4 ящика с усами:
- **Time to goal [s]** — время до входа в радиус 0.3 м у цели
- **Path length [m]** — длина траектории
- **|v| mean [m/s]** — средняя |линейная скорость|
- **|ω| mean [rad/s]** — средняя |угловая скорость| (активность руления)

Что видно из бенчмарка (40 стартов, seed 42):

| Контроллер | Достигают цель | Что заметно |
|---|---|---|
| 🔴 Polar Lyapunov | **92%** | Быстрый (медиана ~3 с), **высокая \|ω\|** — активно крутит руль ради финального угла |
| 🔵 Sampling MPC | **95%** | Медиана ~4 с, **умеренные \|v\| и \|ω\|**, узкое распределение — стабильно подъезжает к цели |
| 🟢 Heading Pursuit | **92%** | Самый быстрый по времени, но **финальный угол не контролируется** |

Финальные углы — в `results/benchmark.json` (поле `final_head_err`).
